# 岗位信息采集规范（全国版 · 给 AI 助手 / 采集 Agent 用）

> 用途：「GIS 人才求职市场可视化大屏」数据采集。本规范扩展自地信实习雷达的采集规范，范围从"武汉实习"扩大为**全国、实习+校招+社招**。

## 任务描述

在网上搜索 **地理信息科学（GIS）/ 测绘 / 遥感 / 地理大数据** 相关岗位的招聘信息（**实习、校园招聘、社会招聘都要**），汇总输出 JSON 文件供 ETL 入库。

**范围：全国，不预设城市清单**——岗位在哪个城市就采哪个城市。一线到十八线都要，小城市的零星岗位同样是数据点（区域分布图需要）。

## 输出格式

JSON 数组（UTF-8，.json），每个岗位一个对象：

| 字段 | 必填 | 说明 |
|---|---|---|
| company | 是 | 公司全名 |
| title | 是 | 岗位名 |
| city | 是 | 城市，如「武汉」「苏州」（直辖市填「北京」等） |
| province | 是 | 省级行政区**全称**：湖北省 / 北京市 / 内蒙古自治区 / 广西壮族自治区（与 DataV GeoAtlas 的 name 一致，用于区域图 join） |
| address | 否 | 尽量具体的办公地址（用于地图定位），没有就留空字符串 |
| job_type | 是 | `intern`（实习）/ `campus`（校招、应届生岗）/ `social`（社招）三选一 |
| requirements | 否 | 招聘要求/职责原文，越完整越好（技能统计的数据源） |
| skills | 否 | 技能标签数组，如 ["ArcGIS","Python"]，尽量从下方词表选 |
| salary | 否 | 薪资**原文**，如「150-200元/天」「2000-4000元/月」「15-25K·13薪」「面议」。不要自己换算，不要编造；没写就留空或写「面议」 |
| source_url | 是 | 信息来源链接：**尽量给岗位详情页**；搜索结果只暴露站点域名时，填该站点域名（如 `https://www.zhipin.com`），同时 source_site 必填。链接必须真实出现过，严禁编造 |
| source_site | 否 | 来源站点名，如「BOSS直聘」「智联招聘」「测绘英才网」「牛客」「公司官网」 |
| collected_date | 是 | 采集日期 YYYY-MM-DD |
| notes | 否 | 备注（更新时间、是否「招聘中」等） |

## 注意事项（质量红线）

1. **宁缺毋滥，严禁编造**：company/title/salary/要求必须来自真实检索到的页面；搜不到具体信息就跳过该条，绝不允许为了凑数编造或「脑补」字段
2. source_url 必须真实可访问；example.com 之类的占位链接一律不允许
3. 信息过旧的（明确写着已截止、停招）不收录；优先「招聘中」且近期更新的
4. 岗位必须与 GIS/测绘/遥感/地理大数据强相关（纯 IT 开发岗不带地理成分的不收；「高德地图导航研发」这类收）
5. 三类岗位都要：一个批次里 intern/campus/social 混合，大致比例不做硬性要求，但不要全是同一类
6. 同一公司多个不同岗位可以各收一条；同一条岗位在不同站点重复出现只收一次（选信息最全的源）
7. city 与 province 要对应正确（苏州市→江苏省），这是区域聚合图的 join 键
8. salary 一律抄原文，禁止换算成统一格式（ETL 负责结构化解析）

## 批次与产出约定

- 产出目录：`collector/batch<N>/<类别>.json`，一个采集任务一个文件
- 文件为合法 JSON 数组，UTF-8 无 BOM
- 采集完自查：JSON 能被解析、必填字段全有、source_url 无重复
