# 项目落地意义 & 简历/面试价值（面试前重读这份）

> 这是写给项目作者自己看的：为什么做这个项目、它在简历上算什么、面试官会从哪些角度问。发布 README 时不要照搬，但面试前应该重读。

## 一、实际落地意义（这个项目"有用"在哪）

### 1. 解决一个真实而具体的痛点
GIS/测绘/遥感专业的招聘信息散落在 BOSS直聘、智联、测绘英才网、各单位官网、微信公众号里，**没有一个垂直聚合渠道**，更没有"行情"视角。计算机专业有 levels.fyi、OfferShow 这类行情工具，地信专业什么都没有。这个大屏回答的是地信学生求职时最实际的四个问题：
- **去哪个城市**：岗位集中在哪、哪些城市被低估（省份/城市着色图直接回答）
- **走哪个方向**：WebGIS 开发、遥感算法、测绘生产三条线的岗位量和薪资对比
- **学什么技能**：技能词频和共现矩阵 = 市场用脚投票的技能需求榜
- **要多少薪水**：分城市/分岗位类型的薪资分布（箱线图），谈 offer 有底

### 2. 数据是自己生产的，不是下载的
市面上 90% 的学生可视化项目用现成数据集（全国房价、疫情数据、人口普查）。本项目的数据管道是自己设计的：采集规范（字段表+受控词表+质量红线）→ 多期滚动采集 → ETL 清洗。这意味着项目能讲"数据治理"，而不是只会讲"图表配置"。且多期采集天然形成时间序列，能看出秋招/春招的周期波动和方向变化（如 GeoAI 类岗位占比上升）。

### 3. 技术栈是政企 GIS 项目的标准缩影
"采集入库 → PostGIS 空间库 → 服务发布（瓦片/OGC 服务）→ WebGIS 前端 → 大屏可视化"正是国土、规划、应急、水利、交通等政企 GIS 项目的标准链路。做完这个项目等于把一条政企项目全流程亲手走了一遍，面试政企方向（中地、超图、南方数码、各省测绘院信息化部门）时可以直接对上话。

### 4. 有可持续性，不是一次性作业
- 开源后其他地信学生可按采集规范 PR 提交数据，项目从个人作品变成社区数据集
- 实习雷达（Flutter app）继续做采集端，大屏做展示端，两个项目互相成就
- 预留 Agent 查询入口（主题 5），项目有明确的演进路线图

## 二、传上 GitHub 后对简历的意义

### 1. 简历项目栏直接可写的两条 bullet（已预置在 PLAN.md）
- 独立设计实现"GIS 人才求职市场可视化大屏"：采集清洗 500+ 条多城市真实岗位数据，构建 PostGIS 空间数据库与 Node.js REST API，基于 AntV L7（WebGL）实现热力图、分级统计、技能共现、城市飞线等 6 类时空可视化
- 打通地图服务全链路：OSM 数据 → MBTiles → tileserver-gl 自托管矢量瓦片服务 → 前端加载，Docker Compose 全栈一键部署

### 2. 与竞争者的差异化（面试官视角）
面试官一学年要看几十份 GIS 学生简历，项目大多是三类：课程设计（"基于 SuperMap 的 XX 查询系统"）、教程复刻（疫情地图、房价可视化、ECharts 大屏模板）、实验室横竖课题的子模块。本项目差异点：
- **数据自产**：能讲清数据从哪来、怎么清洗、怎么保证质量——大多数学生项目讲不了
- **全链路**：从原始 JSON 到屏幕像素每一层都是自己搭的，没有"平台代劳"的部分
- **可演示**：公网链接 + GIF，打开就是 WebGL 大屏，视觉记忆点强
- **持续提交历史**：4 周以上的规律 commit 记录，证明是真实做的而不是一天抄完的

### 3. 关键词覆盖（机器筛简历就吃这套）
PostGIS、空间数据库、空间 SQL、GeoServer、矢量瓦片、OpenLayers、MapLibre、Cesium、AntV L7、WebGL、Vue3、Docker——国内 GIS 开发岗 JD 高频词基本全覆盖。HR 关键词筛选和面试官快速扫简历时命中率显著提高。

## 三、面试意义（会被问什么、怎么接）

### 技术深挖题（准备到能白板讲的程度）
| 面试题 | 项目里的答案素材 |
|---|---|
| 为什么用 PostGIS 不用 MySQL 空间扩展？ | GiST 索引 vs R-tree、ST_DWithin/ST_Buffer 等函数完备性、几何类型系统 |
| GCJ-02 和 WGS84 怎么处理的？ | 双字段制：geom(4326) 做分析、lng/lat(GCJ-02) 做展示；ETL 统一转换一次；边界 GeoJSON 选 DataV（GCJ-02）与底图对齐——这是国内 GIS 面试经典题，你亲手踩过 |
| 瓦片服务原理讲一下 | XYZ 协议、瓦片金字塔、z/x/y 与经纬度换算、栅格 vs 矢量瓦片、为什么 tileserver-gl 要配 style.json |
| 几千个点前端为什么卡，怎么优化？ | WebGL 渲染 vs DOM/SVG 的量级差异；L7 的数据驱动与 GPU 管线；聚合图层减少绘制对象 |
| 热力图是什么原理？ | 核密度估计（KDE）思想 vs 简单计数；权重字段（薪资）如何影响结果 |
| 薪资文本怎么结构化的？ | 正则 + 单位归一（日/月/时薪折算 21.75 天）；解析失败率统计与兜底策略 |
| Docker Compose 里几个服务？怎么编排的？ | postgres+postgis / tileserver-gl / api / nginx 四容器，网络与启动依赖（depends_on + healthcheck） |

### 项目素质题（区分度其实在这）
- **"项目数据怎么来的？"** → 讲采集规范的受控词表设计、质量红线（宁缺毋滥、必须真实链接）、去重策略——展示数据治理意识
- **"遇到过最难的问题？"** → 提前攒 2-3 个真实坑：坐标偏移几百米排查（GCJ-02 混用）、L7 图层遮挡与 pick 冲突、瓦片边界接缝——到时候用真实发生的替换
- **"数据量大 1000 倍怎么办？"** → 分区表、聚合物化视图、前端聚合/抽稀、瓦片预切——方案里预留了这个话头（服务端聚合就是为了这个）
- **"项目有什么不足？"** → 诚实版：样本有采集偏差（AI 检索覆盖面）、单机部署无高可用、无用户增长动作。能主动讲不足 = 工程成熟度

### 反向利用（加分动作）
- 面试时**直接打开公网链接演示**，30 秒胜过 5 分钟描述
- 挑一个踩坑写技术博客（掘金/知乎/CSDN），README 挂链接，反过来给仓库引流
- 过程中如果发现 L7/tileserver-gl 的 bug 或文档错误，提 issue/PR——"开源贡献者"身份比项目本身更值钱

## 四、预期效果的一句话总结

面试官记住你的方式不是"又一个做地图的"，而是"那个自己采数据、自己搭瓦片服务、把地信就业市场做成行情看板的同学"。前半句是能力证明，后半句是选题记忆点——两个都有，项目就成了。
